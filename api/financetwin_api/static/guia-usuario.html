1. Qué es Finance Twin

Finance Twin simula el impacto financiero de una decisión antes de ejecutarla (apertura de local, financiación, contratación, compra de activo, estrés de liquidez, etc.).

Arquitectura conceptual: se construye un twin (snapshot de caja, ingresos y costes). El motor calcula escenarios; la interfaz solo presenta resultados. No hay fórmulas financieras en el navegador.

No sustituye ERP, banco ni asesoramiento fiscal/legal. No incluye chat de IA en esta versión.

2. Arranque

  1. Levante la API (uvicorn en el puerto 8000, o docker compose up).
  2. Abra http://127.0.0.1:8000/.
  3. La pantalla inicial es únicamente gestión de empresas. Sin empresa seleccionada no se habilitan el resto de secciones.
Despliegue local / demo: los datos persisten en SQLite. Auth multi-usuario completa no está integrada en la UI; no trate una instancia pública abierta como multi-tenant seguro sin configurar token de organización.

4. Empresas (paso obligatorio)

  1. Indique nombre (y país) → Crear empresa.
  2. O seleccione una existente → Usar / Editar / Renombrar / Borrar.
  3. Atajo de referencia: Cargar escenario demo (crea empresa demo + twin + cálculo new_site).
Tras crear o usar una empresa, la aplicación abre Datos / twin para elegir la fuente de datos (salvo la demo, que lleva directamente al resultado).

6. Simular una decisión

Sección Decisión, asistente en tres pasos:

  1. Pack — tipo de decisión (new_site, financing, asset_purchase, hiring, generic_investment…).
  2. Hipótesis — inputs del pack y variante Base / Conservador / Adverso.
  3. Calcular escenario — el motor ejecuta; la UI solo muestra.

Comparar escenarios (B/C/A) lanza tres runs con la misma base de hipótesis y presenta la tabla comparativa.

7. Análisis de liquidez

Pack liquidity_plan: no es una inversión, es un estrés de caja.

  1. Defina horizonte y mes de ancla.
  2. Ajuste de ventas (ej. -0.10 = −10 %), opex extra u otras salidas.
  3. Ejecute el cálculo y revise caja mínima y políticas.
El twin debe contener ingresos/costes coherentes. Un twin vacío produce resultados engañosos.

8. Interpretar el resultado

  • Hero (inversión): suele ser el VAN.
  • Hero (liquidez): caja más baja del horizonte.
  • Políticas OK / Atención: cumplimiento de caja mínima y demás checks del motor.
  • Análisis avanzado: comparación B/C/A, sensibilidad, tornado, Monte Carlo (principalmente new_site), informe HTML.
Lectura recomendada:
  1. ¿VAN > 0 con la tasa de descuento usada?
  2. ¿La caja mínima respeta la política?
  3. ¿El escenario adverso sigue siendo aceptable?
  4. Si no: ajustar financiación, CAPEX, timing o descartar la decisión.

9. Twin Loop (plan vs realidad)

Ciclo de aprendizaje: simulación → decisión → realidad → sesgo → calibración.

  1. Registrar decisión (estado Ejecutada si va a cargar reales). Congela el previsto a partir de la simulación.
  2. Registrar valores reales por periodo (YYYY-MM). Solo rellene la columna Real; el previsto viene congelado.
  3. Repita al menos 3 periodos del mismo indicador (p. ej. ventas mensuales).
  4. Calcular perfil de sesgo — mediana de (previsto − real) / previsto.
  5. Previsualizar calibración — si n≥3 y hay mapeo a inputs (p. ej. new_site).
  6. Aplicar calibración — vuelca hipótesis ajustadas al formulario; recalcule el escenario.
Sesgo típico: mediana de la desviación relativa. Positivo = sobreestimación (previsto > real). Negativo = subestimación. Fórmula de calibración: calibrado = valor × (1 − sesgo_mediano). Contabiliza periodos (meses), no solo el número de decisiones.

14. Alcance y límites

Incluido

  • Seis packs MVP, variantes B/C/A, informe HTML.
  • Importación SABI/PGC (heurística), plantilla CSV, entrada manual, demo.
  • Twin Loop completo: decisión → reales → sesgo → calibración.

Fuera de alcance (esta versión)

  • Conectores ERP/banca automáticos.
  • Chat / IA interpretativa (F9 diferida).
  • Multi-tenant SaaS endurecido en UI.
  • Consejo de inversión o fiscal vinculante.
Checklist de primer uso (≈10 min)
  1. Cargar escenario demo → revisar VAN y caja mínima.
  2. Comparar escenarios (B/C/A).
  3. Registrar decisión → 3 periodos de valores reales.
  4. Calcular perfil de sesgo → Previsualizar / Aplicar calibración → recalcular.
  5. Crear una empresa propia e importar o introducir twin realista.
